## 二、推薦順序（新手友好度）

### 第一推薦：`lissy93/domain-locker`

**為什麼**：
- TypeScript 的 web 應用（與你的 web 漏洞背景契合）
- 1,551 stars——**夠小，報告少**（不容易撞題）
- 作者 `lissy93` 活躍（會回應）

**入口**：
- SECURITY.md: https://github.com/lissy93/domain-locker/blob/main/SECURITY.md
- 回報: https://github.com/lissy93/domain-locker/security/advisories/new
- 授權: MIT

**先做什麼**：
1. 讀 SECURITY.md（確認 scope）
2. Clone 專案，本地跑起來
3. 讀 `src/` 的路由與認證邏輯
4. 找「已登入使用者能存取他人資料」的端點

## 四、怎麼用這份清單

### 步驟 1：選一個目標（建議第一推薦）

### 步驟 2：讀 SECURITY.md（**必做**）

**每一份 SECURITY.md 都不同**，常見差異：

| 差異 | 影響 |
|---|---|
| 「請 email 到 security@...」 | 不用開 GitHub advisory |
| 「請用 GitHub Security Advisories」 | 用專案的 advisory 表單 |
| 「我們只接受已確認的 RCE」 | 小漏洞別報 |
| 「不接受 AI 產生的報告」 | **你的 AI 背景反而是風險** |
| 「不接受掃描器輸出」 | 必須手動測試 |

### 步驟 3：本地跑起來

```bash
git clone https://github.com/lissy93/domain-locker
cd domain-locker
# 依 README 安裝依賴
```

**為什麼本地跑**：
- 你能讀原始碼（比黑箱測試有效 10 倍）
- 你能重現、除錯
- **你不會打到生產環境**

### 步驟 4：照 `docs/VDP_REPORT_TEMPLATE.md` 寫報告

### 步驟 5：回報

## 五、重要提醒

### 1. 這不是授權

**清單本身不授權你做任何事**。授權來自：
- 專案的 `SECURITY.md`（明確的漏洞回報政策）
- 或平台 program 的 scope

### 2. 有些專案禁止 AI 輔助

**讀清楚**。近年有些專案明確寫：

> "We do not accept reports generated by AI/LLM tools without human verification."

**如果你用 AI 輔助，報告中要誠實說明**（而且**必須有真人驗證**）。

### 3. 不要打生產環境

**本地 clone + 跑起來**是最安全的方式。

只有在**平台 program 明確授權**的情況下，才對遠端目標測試。

### 4. 新手的第一個目標應該是「小」

- 1k–5k stars 的專案（報告少）
- 你熟悉的語言（Python/TypeScript）
- 作者活躍（會回你）
